# Flora 请求精简

本次保持原认证与花瓣核销架构，不迁移或重写用户数据，不恢复日报埋点。发布顺序为兼容后端、非正式入口跳转、前端；各 Worker 版本与 commit 在发布后单独记录。

## 抽牌

新客户端在本机按账号和项目保存有序、不透明的选牌 token，不存整副牌的身份。牌位先放牌背，选满后由 `draw-picks` 一次事务校验并保存、翻牌；九张牌的正常完整选牌由九次保存请求变为一次。每笔解读的扣费仍由原解锁事务处理。

批量提交校验牌扇、牌阵长度、账号归属、已选前缀与预期版本。已提交的批次重试只返回原进度，乱序或其他标签页的冲突不能覆盖原牌。同一个会话只创建一条原解读，老版 `draw-pick` 保持兼容。

断网或刷新后在同一浏览器恢复本机选择。点击“暂存并返回”会把阶段性进度同步服务器，供其他设备恢复；清除浏览器存储前尚未同步的选择不能跨设备找回。浏览器禁止/耗尽存储时回退为即时服务端同步，保证不会把仅在内存的进度宣传成已保存。

## 刷新与缓存

焦点和可见性事件统一合并，不做周期轮询。当天已经签到的肯定结果可在本机按账号保存到北京时间午夜；未签到结果仍短期检查。项目列表和历史分页复用两分钟缓存，余额复用三十秒缓存；实际充值、签到及解读写入前后仍使相关读缓存失效。

跨标签页通过不含问题、结果和凭据的本机变更通知失效缓存。账号切换和退出清空账号缓存；相同账号的令牌轮换不重复加载整个用户主页。过期登录不能绕过认证读取缓存。服务端扣费/核销不依赖客户端缓存。

## 用户主页

新版 `profile?section=usage|ledger|orders&days=all|7|30` 只装配当前栏目。花瓣流水仅在打开流水栏目后读取，使用现有 `ledger_owner_created` 索引与时间、rowid 游标，每页二十条，支持继续加载全部记录。没有新建索引，也没有删除旧流水。回到窗口仅刷新小型余额信息，不重新装配整页历史和流水。

旧根路径的 overview 返回格式保留给缓存中的旧客户端。正式接口的新增历史路由仍受原历史读取限流和账号归属校验约束。

## 静态公开页面

安全构建只复制明确允许的六个 Next 公共 HTML 外壳：首页、每日牌、是与否、知识、oracle、space，加上五个政策与介绍页面。认证页面、用户主页、项目、充值及兑换不导出为公开文件。账号数据仍在客户端登录后通过认证接口获取。HTML 要求浏览器重新验证，发布时静态资源按新构建整体更新。

公共链接使用原生导航，避免把 HTML 当 Next RSC 解码。旧客户端收到 HTML 时使用 Next 自带的整页导航回退。原版布局、OG 资源和页面文字保持原有来源。

`flora-domain-canonical` 只有非正式入口的跳转代码，没有数据库、AI 或支付绑定。它的 Route 只匹配 `www.floralenormand.site/*` 和 `http://floralenormand.site/*`，在主站静态资源前保留 HTTPS、主域名及路径/查询参数跳转。正式 HTTPS 域名不匹配此 Worker，公开资源可直接由 Static Assets 返回。

## 验证

- 业务测试覆盖九张批量提交、整体回滚、重复/乱序、外部伪造 token、跨账号与旧客户端兼容。
- 本机 journal 测试覆盖刷新、响应丢失、部分已确认、冲突、账号/会话隔离及存储失败。
- 流水测试覆盖同时间记录分页、无重复遗漏、现有索引查询计划及按栏目查询。
- 事件与缓存测试覆盖焦点/可见性合并、跨标签页失效、跨账号与北京时间午夜。
- 本地浏览器实测先选三张后刷新恢复，再补满九张完成原解读。
- 真实 workerd 的资源路由测试确认公共 HTML/HEAD 不进入应用 Worker，私有页面继续走应用；完整生产构建还须通过本地 workerd 页面渲染后才发布。

以上是可复现的功能与路径验证，不将局部减少比例当作全站账单降幅；上线后的实际总量仍受用户访问与爬虫流量影响。
