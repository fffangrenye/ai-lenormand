# 交互式深度占卜（仅本地）

用户确认十字 5 张、H 形 7 张、矩阵 2×3。入口改为先输入问题及选择牌阵，再洗牌并由用户从可滑动牌扇逐张选牌。选满后自动预留 1 花瓣，生成并保存解读；失败释放预留，原牌保留。充值仍未接入，生产网站及模型未调用。

界面 V1 最后调整：结果以问题为大标题、牌阵为小标题。洗牌先进入手动搓牌区域，支持鼠标或手指拖动、键盘操作，也可切换自动洗牌；完成后由用户进入原有选牌阶段。洗牌交互本身不扣花瓣。保存方式与后续顺序见 [V1 保存与下一步](ui-v1-next-steps.md)。

## 固定牌位和适用问题

| 牌阵 | 固定读法 | 适用问题 |
| --- | --- | --- |
| 三张 | 1→2→3，读相邻组合和整条发展 | 单一问题、简短发展 |
| 五张线性 | 第 3 张为核心，读相邻关系与首尾呼应 | 阶段进展与转折 |
| 六张矩阵 | 上排 1–3 表层，下排 4–6 深层；同列对照，无单一中心 | 表里差异、局面分析 |
| 五张十字 | 1 中心，2 左前因，3 右趋势，4 上期待，5 下现实基础；读 2→1→3 及 4→1→5 | 困境、卡点及行动空间 |
| 六张二选一 | A 为 1–3，B 为 4–6，各自竖排起点→过程→趋势 | 两个具体选项的比较 |
| 九张三选一 | A 为 1–3，B 为 4–6，C 为 7–9，各自独立发展 | 三个方案的条件与代价比较 |
| 七张 H | 左列 1–3 我方，中间 4 连接点，右列 5–7 对方；再读 2→4→6 | 关系、合作和谈判 |
| 九宫格 | 中心 5；横排思想／现实／基础，纵列过去／当下／趋势；再选少量对角与镜像辅助 | 多因素主题的全貌 |

这些是本站明确展示的固定版本，并非声称所有雷诺曼流派只有一种排法。矩阵、十字、H 和选择牌阵采用站内公开的牌位约定。选择题必须填写不同的具体选项，以相同目标和时间范围比较；不能跨分支拼接组合。H 不当作读心证据。三选一虽有九张，也不能套用九宫格中心规则。

九宫格的中心、横纵线、四角与对角线参考了作者 Tina Gong 的 [Labyrinthos 九张牌阵说明](https://labyrinthos.co/blogs/learn-tarot-with-labyrinthos-academy/how-to-read-nine-card-portrait-box-or-3x3-lenormand-spreads)。通用组合方法沿用项目已核验书籍摘要。没有宣称整书知识库完成，也没有混用未确认的专用计时体系。

## 持久化与防重复

`003_interactive_spreads.sql` 仅升级 `.local-paid` SQLite：保留原解读、牌面、结果、追问、流水和关联；新增牌阵类型、选项及洗牌会话。没有生产迁移或部署。

洗牌由服务端随机排列 36 张牌，浏览器只收到随机令牌和已抽状态。每次点选只提交会话 ID、卡背令牌和预期进度；服务端查归属、查进度、拒绝伪造令牌，并原子保存选牌顺序。未抽牌面不返回客户端。重复选择同一令牌不重复抽牌；刷新继续原会话；暂存未完成抽牌不扣花瓣。最后一张完成时固定保存原牌，解读复用原有原子预留、提交结果和扣除机制。

新用户进入深度占卜会幂等创建默认项目，直接进入问题页面；仍可在项目抽屉管理不同主题。历史按主问题时间从上到下排列，每个问题的完整解读、行动建议与附属追问保存在同一个区块，不再使用全局聊天输入框。用户主页保留消费与余额管理。

## 解读质量的实际状态

服务器提示词 `paid-main-v2-spreads` 恢复原 AI 的“先回应问题、组合优先、自然叙述”原则，按当前牌阵注入独立牌位、路径、选项、项目背景与长期记忆。要求更细致的依据、条件和 2–3 条可执行建议；三张目标 600–800 字、五张 800–1000 字、六至九张 1000–1400 字，避免凑字数。

本地仍使用明确标识的模板模拟稿，已停止将旧规则引擎的“结构倾向”等标签作为新解读输出。该模拟只验收牌阵路径、内容结构、选牌和消费流程，不能代表真实 AI 的细腻程度。真实模型尚未接入，实际质量、长度、耗时和成本仍需在隔离模型环境验证。原历史结果保留，不擅自重写或补扣花瓣。

## 验证

`npm run test:paid-local` 包含八种牌阵、选择题约束、原牌保存、刷新恢复、重复及过期点选、越权、接口整合，以及旧数据库升级后牌面／结果／追问／余额／外键保持。另执行原有每日额度、Yes or No、规则引擎授权与灰度测试、类型检查和构建。页面人工验证 H 形选牌、自动解读、附属追问及手机响应式布局。
