# 2026-10-24 正式站额度故障修复记录

已发布至 https://floralenormand.site 。修复分支：`codex/quota-hotfix-20261024`。本记录与 JSON 回执保存两个 Worker 的独立源码版本，文档提交不代表重新部署。

## 已确认的问题与处理

1. `lib/paid-local/ledger.ts` 的完成时间查询按每条历史记录扫描 `reading_runs`。旧档案没有原完成时间时也会触发查询。现在旧档案直接采用原时间或创建时间；新记录从当前用户的消费流水索引定位任务主键，消除全站任务扫描。
2. 一页 20 条完整历史原先逐条查询追问、项目关联及完成时间，最多 65 次 SQL。现在整页批量装配，旧档案页 6 次、含新解读的页面最多 7 次。分页游标采用用户范围内的时间与 ID 比较，继续保留同时间记录，未使用 OFFSET。
3. 项目列表原先每次检查旧体验记录是否关联项目。现在每个用户在当前进程内检查一次；出现新未关联记录时使该检查失效，兼容本地体验数据。首次检查采用 LIMIT 1，省去 count。
4. 请求采样确认充值菜单调用不存在的 `/catalog`，浏览器还自动预加载多处页面。菜单改为 `/card-catalog`；两个路径的公开套餐信息由后端直接返回，不再访问数据库或身份服务。旧客户端无需等刷新即可得到兼容响应。
5. 关闭 47 处链接的自动视口预加载。项目访问时间更新按账号和项目合并，5 分钟内复用成功结果，不再清空整页历史缓存。正式用户主页不再查询仅用于本地模拟的订单接口。
6. 新增慢 SQL 行数诊断：仅记录查询模板、读取/写入/返回行数；不记录绑定参数、身份、问题、结果或充值码，不向数据库写入埋点。同一模板最多每分钟一条。
