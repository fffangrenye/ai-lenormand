## 产品规则

- 首页右上角独立“今日签到”，点击即抽今日牌并签到；未登录则先登录并继续本次签到。已签到显示“今日已签”，点击直达牌面日历。首页每日运势和用户主页的日历入口继续保留，日运页日历入口加为明显的按钮。
- 登录后的“签到，领取今日运势”“抽取今日牌”和日历上的“今日待抽”调用同一服务端操作。
- 按北京时间 `Asia/Shanghai` 每日 00:00 切日，每个账号每天只有一条签到和一张今日牌。再次打开或重试返回同一张牌和同一份已保存运势。服务端生成日期与牌面，不接受客户端补签、改日期或指定牌。
- 普通浏览日历、打开日运、链接预取不会自动签到；只有点击签到／抽牌或进入签到按钮对应的 `/daily?checkin=1` 才提交。处理后移除参数，刷新只查看已存内容。午夜或重新获得焦点时同步新的一天。
- 日历显示有签到日期的牌图和牌名，点击可打开当日完整运势。过去未签日期和未来日期不可抽牌，不补签。
- **2026-10-21 按用户最新要求改为连续签到奖励**：每连续满 3 天送 1 花瓣，同一段连签中的第 3、6、9……天自动到账。漏签一天后重新计算，跨月、跨年不打断连续性。今天未签但昨天已签时保留昨天的进度，今天仍能接上。没有额外领奖按钮。
- 历史总签到天数和日历继续保留，旧累计规则已经到账的花瓣不收回。奖励长期有效，解锁一次完整解读及其两次追问；新流水标记“连续签到 N 天奖励”。新用户一次性赠送 5 次不变。
- 显示连续天数、历史总天数、本轮 0–3 天进度、下一奖励所需天数、已到账奖励数及提示。
- 首页展开后的三个入口保留原图内全部文字（编号、中英文标题、说明），改为轻边框、留白、细线花朵及沙漏／吊坠／月镜，沿用奶油、灰绿、陶粉、蓝灰；桌面三列，窄屏上下排列。首页原有带 Lenormand 字样的呼吸牌背保持原样。

## 数据与接口

`004_daily_check_ins.sql` 保留每日牌和旧累计奖励表。增量迁移 `005_consecutive_check_ins.sql` 新增连续奖励表，保留原有账户、花瓣、抽牌、解读及旧奖励记录。

- 每日记录主键 `(user_id,date_key)`，保存牌与运势的 JSON 快照。
- 新奖励主键 `(user_id,streak_start,milestone)`，同一账号同一天唯一，赠送事件键 `checkin:consecutive:账号:连签开始日期:连续天数`。只有当日首次签到且连续天数整除 3 时发奖，旧日期重复签到不补发新规则奖励；奖励统计包含已得旧奖励。
- 签到、里程碑、花瓣批次和消费流水在同一个 SQLite `BEGIN IMMEDIATE` 事务内提交。并发、双击及响应丢失后的重试不会重复签到或发奖。
- `GET /api/local-paid/daily?month=YYYY-MM` 返回所属账号日历、今日牌、`currentStreak` 连续天数、`totalDays` 历史天数、本轮进度、余额及切日时间。
- `POST /api/local-paid/daily-check-in` 不接收日期或牌面参数，返回今日牌及本次新发的奖励里程碑。

每日运势沿用原每日牌的规则文案，不调用真实 AI，不扣花瓣。深度解读仍可使用真实 DeepSeek。本地 V2 页面要求登录后保存账号记录；未开启本地测试模式时，原站每日运势页面继续沿用原流程。
