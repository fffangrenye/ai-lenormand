# 雷诺曼 V3：本地购买与支付

本轮在 V2 基础上开发，未部署、未接真实收款，未运行线上数据库迁移。V2 归档保持原样；用户确认后按 V3 保存一次代码包和单独的本地数据快照。

## 预览与入口

- 启动本地真实 AI 预览：`npm run dev:paid-local:ai`，地址 `http://127.0.0.1:3100/`。支付仍为模拟；只有主动生成解读才会消耗 AI API。
- 无 AI 费用预览：`npm run dev:paid-local`。
- 充值：`/recharge`；消费与订单：`/profile`；管理：`/admin/paid-local`。
- 管理口令在本机 `.local-paid/admin-access.txt`，首次启动自动生成。与用户登录分开，管理会话两小时有效，5 次错误尝试后冷却 15 分钟。不要公开口令文件。
- 本地资料继续使用 `.local-paid/v1.sqlite`，保留 V1/V2 数据，不因版本号另开丢失历史的数据库。
- 反馈邮箱：`FFFangrenye@outlook.com`，加入充值和用户主页。公开域名的已有联系页未部署修改。

## 固定套餐价格

免费试用为每账号一次性 3 次，不是每天刷新。沿用原赠送事件标识，重登不重复赠送。本地原 5 次试用批次只调减尚未使用的超额部分，购买、签到奖励、已完成解读和正在生成的任务均保留；预留任务失败释放后重新核对剩余试用额度，账本记录调整。

| 花瓣（完整解读次数） | 固定价 CNY |
| --- | --- |
| 1 | 4.99 元 |
| 5 | 14.99 元 |
| 10 | 24.99 元 |

每花瓣包含一篇完整主解读和两次追问，长期有效。2026-10-22 用户取消首充半价，首次和后续充值均使用以上固定金额。历史订单保留原成交金额，退款按该单实际支付计算。

价格、币种、套餐与原问题跳转都由服务端确定并保存订单快照。每账号同时仅能新建一笔待付款或处理中订单，需核实的异常订单会阻止新建，避免重复充值。

## 已实现的本地流程

选择套餐和微信 Native / Waffo 银行卡 → 确认创建订单 → 展示明确标记的模拟二维码 → 模拟渠道付款凭据 → 签名验证与订单金额/币种/渠道匹配 → 原子增加购买花瓣 → 可返回原问题继续。付款本身不会自动调用 AI 或扣解读花瓣。

二维码编码的是本机订单链接，**无法真实付款**。微信官方 Native 的 `code_url` 必须由获批商户 API 返回。官方文档要求微信“扫一扫”，不支持从相册识别二维码。Waffo 当前同样没有调用正式收银台。

- 订单 15 分钟有效；查询和重新打开恢复状态。
- 可以模拟成功、失败、15 秒延迟、金额不一致、已付款未发货和重复通知。
- 订单创建请求、渠道流水、付款事件和发放批次都有唯一标识；事务保护核款与一次发放，多进程重复通知也只到账一次。
- 签名为仅本地模拟使用的 HMAC，不能用于真实微信/Waffo 通知验签。
- 用户只能查自己的订单、付款和退款；管理接口需要独立管理会话。请求限制为回环地址、同源与本地测试请求头。
- 后台查询用户、余额、订单，核款并补发，单独补偿花瓣，发起退款、模拟退款成功/失败，保留操作原因与日志。没有渠道成功凭据不能直接把未付款订单标为已付。
- 展示最近 200 笔订单/日志，原记录仍留在数据库。

## 退款约定（本地验证规则）

本单未使用花瓣可申请退款，退款额为 `floor(本单实付分 × 可退花瓣 / 购买花瓣)`。申请时冻结对应购买批次，其他购买和赠送不受影响。已有预留花瓣的购买需等解读结束再处理。

模拟渠道退款成功后保留撤回记录；失败则恢复冻结花瓣。已消耗花瓣不退。异常金额且未发货的订单按实际模拟收款金额退回。此处是可验证的产品处理规则，不代表真实渠道已经支持退款；正式开放前须与公开退款政策及渠道能力统一。

## 接真实支付前仍须完成

1. 获得实际业务的商户/渠道批准。Waffo 提供的政策将占卜命理列为“仅卡组织”，不能据此承诺微信受理。
2. 微信：获批商户号、AppID、API v3 密钥、商户私钥与证书序列号、微信支付公钥/证书配置、HTTPS 通知地址。不要把秘密粘贴到聊天或前端。
3. Waffo：获批账号、官方接口与验签文档、密钥、可用币种/渠道、订单查询和退款能力，届时确认人民币价格结算是否支持。
4. 用官方文档实现真实下单、通知验签、解密、主动查单、关单、退款及退款查询；模拟 HMAC/二维码不可直接当正式接口用。
5. 将本地 SQLite 事务与唯一约束迁移到正式持久化存储，接入正式账号、后台权限及管理审计。当前 `/api/local-paid` 在 production 环境拒绝运行，不能直接部署后收款。
6. 确认价格/公开条款及退款说明，完成渠道测试后单独授权部署，保留原网址的运行与回滚安排。

## 验证

`npm run test:paid-local` 覆盖原有权益、签到、抽牌、真实模型适配的模拟测试和 V3 支付测试。V3 特别验证新老账号价格一致、取消/失败/过期、延迟重启恢复、重复通知并发防重、异常签名和金额、补发、补偿、部分/全额退款、退款失败恢复、原问题归属、越权与独立后台会话。

浏览器也验证了建单 → 模拟成功到账 → 退款申请冻结 → 后台模拟退款的页面流程。测试生成的本地模拟订单保留可查询；没有真实资金操作。
