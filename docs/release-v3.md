## 正式上线顺序

当前状态：用户已确认微信和 Waffo 均尚未取得获批的 API 权限。下一步首先完成渠道受理确认和商户审核；正式支付开发以获批能力及官方接口文档为准。

1. 先取得按实际占卜/AIGC 业务获批的渠道 API 权限，确认主体资格、支付方式、人民币金额是否受理、结算与退款规则。Waffo 的域名 TXT 验证不等于支付审核通过，用户提供的限制政策将占卜命理列为仅卡组织，需向平台确认实际可用渠道。
2. 代码先保存到 GitHub 独立分支，核查现有仓库是否连着自动部署，避免推送开发版影响旧站。公开仓库不得包含环境配置、商户私钥、本地管理口令、用户或测试数据库。
3. 把本地测试账号、SQLite、模拟支付换成正式认证、持久化账本、管理员权限和真实支付适配。模拟路径生产环境拒绝运行，不能通过解除保护直接上线。
4. 在独立、受限的公网测试环境接收 HTTPS 支付通知，验证验签、金额、主动查单、延迟/重复通知、退款及故障恢复。与真实渠道联调通常需要公网地址，不能等全部本机测试结束后才第一次验证回调。
5. 完成新域名登录回调、站点地址、条款、隐私、退款及联系信息配置，再将完整站切到 `floralenormand.site`；旧 flora Worker 保持现状。现有新域名介绍站需有明确切换和回滚安排。
6. 由用户在新站完成真实网络下的小额付款、到账、返回原问题和退款测试；检查手机入口与两次追问，确认数据、费用和异常处理。
7. 新站通过验收后，最后把旧 `flora.soul-ai-frontend.workers.dev` 配置为到新域名的跳转，保留合法路径及查询参数。测试期可先临时跳转，稳定后再永久跳转，并核对其他旧入口避免形成循环。

如果新旧站使用不同登录或数据来源，迁移账号和历史需在正式切换前完成。测试数据不能直接当正式用户数据发布。
