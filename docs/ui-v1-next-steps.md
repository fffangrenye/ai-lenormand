# 界面 V1 保存与下一步

当前版本命名为“雷诺曼 V1”。界面范围：原站框架、账户菜单、消费主页、八种牌阵选择、手动搓牌／自动洗牌、半圆牌扇选牌、问题大标题、完整解读与附属追问、自适应布局。支持本地模拟和主动开启的真实 DeepSeek 测试，未上线、未接真实支付、未切换生产数据库。开启方法见 [本地真实 AI 测试](lenormand-v1-local-ai.md)。

牌背细化：只有首页原有呼吸牌保留带字设计与原动画。其余翻牌背面、每日运势、Yes/No、深度占卜洗牌、选牌与过场统一使用 `public/cards/quiet-card-back.svg`，米白底搭配灰绿、浅陶色的细密无字暗纹。手动洗牌采用 36 张独立牌张，手经过的局部受到推动、旋转并缓慢滑停，旋转后的牌角也限制在桌面范围内；自动洗牌沿用相同桌面逻辑。支持手机、鼠标、方向键以及减少动态效果设置。此阶段只负责视觉交互，实际隐藏牌序仍在进入选牌时由服务端创建，计费时点与抽牌规则保持原流程。

## 保存与恢复

文件已经保存在工作目录。当前开发分支为 `codex/paid-flow-local-v1`；未提交的改动尚不属于 Git 历史，分支名称本身不是备份。

在本机运行 `npm run backup:local-v1`，生成 `.local-paid/backups/ui-v1-时间-随机标识/`。代码压缩包包含未提交和新增的源文件，生成后解压并逐文件核对哈希；测试数据使用 SQLite 一致性备份单独保存。密钥、`.env`、测试数据库不放进代码包。

恢复代码时解压到新空目录，使用 Node.js 24，按 `pnpm-lock.yaml` 安装依赖，再运行 `npm run dev:paid-local`。需要恢复测试记录时，先关闭本地服务，把单独的数据快照放到恢复目录 `.local-paid/v1.sqlite`。代码备份不包含生产配置，原机器配置不受影响。

建议把生成的备份文件夹再复制到另一个磁盘保存。后续可以在核对自动部署规则后，把经过检查的源代码提交并推送到独立开发分支；不合并生产分支。仓库内现有构建检查工作流只监听 `cf-linux-build-check` 推送与手动触发，但托管平台侧 Git 集成设置尚未核对，因此不能把“推送开发分支”等同于“一定不会发生任何部署”。

GitHub 用于源码版本备份；本地测试记录、真实用户数据和密钥不作为源码上传。此次没有推送。

## 牌阵规则是否还要讨论

建议继续确认解读规则。已有的八种布局和阅读路径见 [交互式牌阵规则](interactive-spreads-local.md)，无需从零开始。矩阵、十字、H 和选择牌阵有多种流派版本，应明确采用本站展示的固定牌位；不要让不同对话各自重新定义。

可与 ChatGPT 逐阵审阅，也可以结合你认可的书籍或老师版本核对；最终以你确认的规则和样例作为验收标准。每个牌阵需要确认六件事：适用问题、每个牌位的含义、组合读取顺序、信号冲突时的优先级、不能推断的内容、行动建议如何落地。

可复制以下需求开展下一轮讨论：

> 我在做花语雷诺曼网站，界面 V1 已定。请根据附带的牌阵规则审阅解读逻辑，不要重新设计页面。我们采用：三张线性、五张线性、六张 2×3 矩阵、五张十字、六张二选一、九张三选一、七张 H、九宫格。先从一个牌阵开始确认牌位、相邻组合与整体叙事的优先级、适用与不适用问题、信号冲突、时间范围及行动建议。每个牌阵给出固定牌面样例、合格解读和常见误读。不同流派请标明差异，由我选择，不要混成一套。H 不当作读心证据，三选一的九张不能套用九宫格规则。最终整理成可以直接用于程序验收的规则文档。

## 后续顺序

1. 冻结界面 V1，保存快照；确认八种牌阵规则。每个牌阵挑 3–5 组固定问题和牌面作为质量样例，再覆盖几个容易误读或条件冲突的例子。
2. 使用已接入的本地真实 AI 模式，沿用同一批样例比较结果，检查是否答题、是否有牌面依据、是否乱加事实、建议是否具体，以及等待时间和费用。技术连通和模拟模板不能代替质量验收。
3. 完成付费业务 V2：每日运势与签到、累计每 3 天奖励 1 花瓣、签到并发防重。一次性赠送 5 花瓣已在本地实现。
4. 完成付费业务 V3：订单锁价、支付沙盒、重复回调防重、支付到账、失败与补偿、退款及消费对账。用户主页已有入口，充值尚未真实接入。
5. 将本地 SQLite 适配迁入独立测试数据库，核对登录、所有权、服务端扣除、重试和历史迁移；完成整站验收后，再安排一次正式上线。

界面 V1 完成不等于付费版已可上线。正式数据库、真实 AI 与支付渠道仍分别需要隔离测试。
