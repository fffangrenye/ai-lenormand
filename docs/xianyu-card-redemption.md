## 用户操作

1. 登录 Flora，在 `/recharge` 查看套餐并点击购买。手机优先使用 `fleamarket://item?id=商品ID` 唤起闲鱼 App，电脑继续打开网页；唤起受阻时可复制用户提供的官方分享链接到闲鱼，或选择网页购买。直接使用用户点击触发，不通过定时跳转推断安装状态，不会在用户返回 Flora 后再次自动唤起。
2. 在闲鱼付款，由配置好的卡密库存发出该档兑换码。
3. 返回 `/redeem`，粘贴码并确认当前账号，再点击立即兑换。
4. 服务器确认码有效，在 SQLite 同一个事务中核销、增加购买批次、写入流水；返回本次权益及当前可用花瓣。
5. 用户主页的充值订单页签展示兑换记录；从原问题进入的兑换保留原问题链接。

重复提交或刷新后重新兑换同一码不会重复加花瓣。同码被另一账号兑换时，返回通用无效提示，不泄露兑换者。账号在表单打开后变化时拒绝兑换。失败事务全部回滚；每账号每分钟最多十次尝试，限流记录不会因兑换失败回滚。

## 管理与导出

正式站 `/admin/codes` 的充值码管理支持按套餐生成每批 1～500 个不同的码、导出未兑换码 TXT、按尾号／记录 ID／批次／兑换账号查询、停用未兑换码，以及登记已核实的闲鱼全额退款。本地隔离环境入口为 `/admin/paid-local`。

数据库只保存充值码哈希和尾号。原码以独立用途的 HMAC 从随机 UUID 与签名密钥推导，只在管理员导出接口返回，可下载 TXT 或从导出区复制；普通列表和日志不包含原码。正式签名密钥由 Cloudflare Secret 保管，本地测试使用隔离密钥；保留密钥，否则旧批次不能再次导出。再次导出同一批次得到相同的未兑换码，不是新库存，不能重复导入闲管家。

资金退款由运营者在闲鱼核实与处理。此处不发起转账：未兑换码作废；已兑换码仅撤回该购买批次未使用的花瓣；已使用或正在解读部分标记人工核对，不扣其他购买或赠送花瓣，不出现负数。预留释放后可再次核对。

## 闲管家库存配置

1. 为 1、5、10 花瓣分别建立独立卡种／库存并对应各自商品，不混码。
2. 导入 TXT，一行一条充值码，采用单次库存发卡；买家每购买一份，发一条。
3. 不用固定内容／无卡发货来发送同一个码；不要重新把已售码标记为未售。
4. 发码成功后由发货工具将该条出库，下一单取下一条；低库存时补充新批次。不要重复导入之前已导出的同一批码。
5. 同一商品不要同时开启直充和卡密；官方手册说明同时开启时直充优先。先检查当前商品的发货模式，再做实际付款验证。

官方操作手册：https://m.goofish.pro/app/operation.html （卡密仓库、自动发货设置、多规格单独设置）。仅开通鱼小铺不代表卡密库存与自动发货已经配置完成。

## 本地与正式售卖的边界

正式站已部署在 `floralenormand.site`，复用 Supabase 登录身份，使用独立 Cloudflare SQLite Durable Object 保存新版项目、签到、花瓣与卡密。正式码以 `FLORA-` 开头。本地 `FLLOCAL-` 码仍只用于本机测试，不能正式售卖。

2026-10-22：用户确认三档商品和自动发卡库存已设置，网站三档购买入口开放。真实付款与自动发码仍需用户用实际订单验证；网站跳转和返回本身都不是付款成功凭证。手机 App 是否被系统成功打开也需真机验证，不能用桌面浏览器测试代替。

唤起方案参考闲鱼技术团队文章：https://developer.aliyun.com/article/801520 。不同客户端和浏览器会限制外部 App 跳转，因此保留明确的复制链接与网页购买入口。
