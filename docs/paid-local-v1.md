# 付费本地 V1：体验与测试说明

日期：2026-10-20。分支：`codex/paid-flow-local-v1`。

本版已按反馈接回原网站的首页、登录入口、深度占卜、项目抽屉、长期记忆、原牌阵选择、抽牌动画、结果与追问组件。只替换本地测试的数据适配层，并在原页面中加入次数和解锁功能，不再把独立原型界面作为产品入口。

使用本机 SQLite 和三个测试账号。未部署、未推送、未连接生产数据库、未进行真实支付，也未向线上账号发放次数。原网站的每日额度及线上登录流程尚未切换。

## 如何打开

在项目目录 `D:\塔罗文件\测试\frontend` 打开终端，执行：

```powershell
npm run dev:paid-local
```

打开原站本地首页：<http://127.0.0.1:3100/>。旧 `/local-paid` 地址会自动返回首页。

体验路径：原首页翻牌 → 深度占卜 → 本地测试登录 → 输入问题及选择牌阵 → 洗牌 → 从牌扇逐张选牌填入虚线布局 → 选满后自动解读 → 完整结果与下方附属追问。项目仍可在抽屉管理。八种牌阵及当前规则见 [交互式占卜说明](interactive-spreads-local.md)。

当前机器已有依赖，直接启动即可；新环境需 Node.js 24 LTS 与项目依赖。项目现有锁文件为 `pnpm-lock.yaml`，新环境按该锁文件安装，勿另行更新生产依赖。

需要其他端口时：

```powershell
$env:PAID_LOCAL_PORT = '3101'
npm run dev:paid-local
```

同一时间只运行一份本地付费开发服务。不要用普通 `npm run dev` 替代上述隔离启动命令。

启动器会：

- 绑定 `127.0.0.1`，不向局域网或公网开放。
- 在子进程中清空生产数据库及模型凭据，将旧数据接口设为不可连接的本机地址。
- 使用 `.next-paid-local/` 编译目录，与原 `.next/` 分离。
- 将数据保存在 `.local-paid/v1.sqlite`；关闭或重启服务不会清空次数和历史。
- 保留原页面与路径；仅拦截旧生产 API，并让原项目页面的数据请求转向 `/api/local-paid`，防止误操作生产流程。本地登录不输入或验证真实网站密码。
- 只运行模拟模型，没有真实支付宝或 PayPal 调用。

若隔离环境未开启、数据库地址不安全或存在模型 / 数据库生产凭据，测试接口拒绝工作。生产模式即使误设本地开关也拒绝使用测试接口和账号。

配置集中在 `lib/paid-local/config.ts`。例如本地测试的默认值为：

```typescript
welcomeCredits: 5,
followUpsPerReading: 2,
reservationLeaseMs: 120_000,
maxDrawsPerWindow: 8,
promotion: { enabled: true, version: "launch-v1", startsAt: null, endsAt: null }
```

不需要复制任何生产密钥到测试配置，也不需要修改现有 `.env.local` 或 `.env.production`。

## 当前可以体验什么

1. 新用户、老用户与独立测试账号各一次性赠送 5 次。切换、刷新、退出再登录都不重复赠送。
2. 三张与五张牌阵：先抽取并保存牌面，不扣次数；点击“开始深度解读 · 使用 1 次”才预留额度。
3. 生成、结果保存与正式扣次：同一记录重复解锁不重复扣次；结果已保存时能够重新打开。
4. 余额、预留数、已使用数及次数账本。赠送批次先于购买批次使用；同类先用较早获得的批次。
5. 每份完成的主解读有 2 次追问。追问沿用原牌，不重新抽牌，不另扣主解读次数，失败不计次。
6. 主解读余额为零，仍能查看已解锁结果和使用这些记录剩余的追问。
7. 零余额可以保存新牌面，解锁时提示次数不足；未返回完整解读、内部提示词或复制 Prompt。
8. 套餐配置预览，活动价为 499 / 1499 / 2499 分，活动关闭为 499 / 1999 / 2999 分；本版不创建订单。

本地没有管理员无限额度绕过：三个账号都按普通用户规则扣次，避免验收时看不出余额限制。正式管理员权益留待后续产品决策。原先独立原型产生的牌面会归入“本地体验记录”项目，已有次数和结果不变。

## 手动测试步骤

### 一次性赠送与保存

从原首页进入深度占卜，尚未登录时选择“新用户体验账号”，首次显示 5 次。在原项目抽屉中新建项目，再使用原牌阵选择与问题输入页；抽牌后仍是 5 次，在原结果页解锁后为 4 次，预留归零。刷新页面或重新登录，仍是 4 次，牌面及结果不变。

选择“老用户”会进入另一套独立数据并获得一次性 5 次，不读取或导入真实老用户记录。

### 两次追问与零余额

主解读成功后显示剩余追问 2/2。成功追问后依次为 1/2、0/2；第三次按钮停用，接口也拒绝。可继续生成其他主解读直到余额为零，再打开未用完追问的已解锁记录，仍可追问。

余额归零后开启新问题并保存牌面，点击解锁会提示次数不足。原牌面保留，没有完整解读或复制 Prompt 入口。

本版不提供任意补余额入口；签到和模拟购买后续接入同一账本。测试“获得次数后沿用原牌”所需的状态与解锁接口已具备，但用户页面获取额外次数的闭环尚未开放。

### 生成失败

失败和断网模拟保留在自动测试中，不在原站的正常用户流程里增加开发工具面板。自动测试会让未解锁记录生成失败，验证可用次数恢复、沿用原牌重试。

自动测试亦验证已完成记录的追问失败：剩余追问次数恢复，可用同一请求标识重试；原站界面遇到失败时会保留输入内容。

### 保存后响应丢失

自动测试模拟解锁成功保存后返回失败响应，确认刷新能找回结果、次数只使用一次。原页面若遇到此类网络问题，应刷新原记录检查结果。

不要因为浏览器看到失败提示就再次创建新问题。原记录才是结果恢复入口。

### 超时与并发

预留租约为 2 分钟。超过期限未完成的任务，在读取账号总览或再次请求时自动恢复。页面每 15 秒同步一次；不会对已完成记录退款。迟到的旧任务结果不得覆盖新任务。

可控时钟和多进程竞争在自动测试里验证，不需修改电脑日期或生产记录。界面没有伪造签到日期入口，签到属于 V2。

### 支付

V1 没有支付按钮、订单或模拟支付通知；套餐只是预览，不会收款。支付成功、失败、取消、延迟和重复通知将在 V3 验证。

## 本地迁移、数据与后续数据库工作

迁移文件：`lib/paid-local/migrations/001_v1.sql` 、`002_original_projects.sql` 与 `003_interactive_spreads.sql`，只适用于本地 SQLite，启动时幂等初始化。第二份迁移加入原站项目与牌面关联，背景和长期记忆也保存在本地服务端。

当前持久化表包括本地用户与会话、权益批次、次数账本、固定牌面解读记录、解读任务及追问任务。事务使用 `BEGIN IMMEDIATE`；数据库约束防止负余额及单条记录重复占用。结果保存、权益消费、任务完成及流水同事务提交。

本机未发现可用 Docker 或 Supabase CLI，因此未生成可宣称已验收的 PostgreSQL 上线迁移，也没有验证真实 Supabase 的 RLS、云数据库并发与生产部署兼容性。下一阶段仍应先准备隔离 Supabase 环境，完成该适配及权限测试；不能直接部署此 SQLite 测试实现。

历史追问的本地兼容规则为“每份总共 2 次减去已有成功回答数”，不会为旧记录重新赠送额外两次；测试保留已有结果、不补扣主解读次数。未向真实历史用户执行该迁移。

## 解读质量与书籍核验

当前主解读基线：原 AI 提示词约 300–500 中文字，1400 输出 token，45 秒超时；追问为 420 输出 token。

已新增独立的付费主解读提示词：三张目标 600–800 中文字，五张目标 800–1000 中文字；输出上限配置 2800 token、超时 60 秒，追问仍保留 420 token。提示词覆盖先回应问题、牌位及组合证据、条件与其他解释、具体行动；不会为了字数编造事实。

这些设置尚未连接真实模型。当前新解读已切换为根据对应牌阵路径生成的本地模板模拟稿，旧规则库模拟结果仅保留在历史记录中，不伪装为已验证结论。因此本版可以验证内容结构与流程，不能据此认定真实 AI 质量已经翻倍。

## 下一版

### 原站交互升级（本地）

保留原站纸张色、酒红色、项目抽屉和记忆功能。按最新反馈撤销全局聊天布局：每个主问题的牌面、详细解读、建议和追问保持在同一区块，最新主问题排最下方。新占卜先进入问题与八种牌阵选择，再进行手动洗牌、抽牌和解读过场。充值仍为下拉套餐，流水集中在用户主页。详见 [交互式深度占卜](interactive-spreads-local.md)。

`/profile` 读取当前本地登录账号的服务端余额、消耗、预留、解读记录和最近 200 条花瓣流水，支持全部／近 30 天／近 7 天筛选。解读消耗时间从实际扣除流水关联获取，不用抽牌时间冒充消费时间。`/recharge` 支持套餐选择与价格预览；尚无支付订单，不生成假订单或实际充值。前台称为“花瓣”，当前与既有权益按 1:1 展示，1 花瓣解锁 1 次主解读及 2 次追问；赠送和计费规则未改变。

首页、每日运势、Yes or No 同步使用账户导航与响应式宽度，首页保留翻牌交互，在宽屏横向展示三个入口。所有新界面仍经本地隔离 API，未部署或修改生产数据。

V2：登录后的每日运势与签到共用同日记录、月历、累计签到天数、每满 3 天自动赠送 1 次，并处理并发和跨月。

V3：锁价订单、本地模拟支付宝 / PayPal、重复通知防重、到账返回原牌，以及管理员核款、补偿和订单批次退款。

真实支付渠道、PayPal 结算币种、真实退款与正式上线仍未接入。
